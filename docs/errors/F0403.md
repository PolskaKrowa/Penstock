# F0403: strided access wastes cache lines

`cache-stride` · warning · error with `--strict-performance` when a single element already costs a full cache line

An access of the form `p[i * K]` with a constant `K > 1` touches only one
element per `K` elements, so most of every fetched cache line is unused.
Elements smaller than 8 bytes are ignored (the hardware copes).

- If one element's stride is at least one cache line (64 bytes), the
  diagnostic is a warning, or an error under `--strict-performance`, and
  reports the line efficiency.
- Below one cache line it is always a warning and only reports the
  bytes per element.

**Fix:** traverse with unit stride, block the traversal, or change the
layout (for arrays of structs, see `F0408`).
