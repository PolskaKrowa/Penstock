# F0211 — narrowing numeric cast

A numeric cast reduces the number of bits available to represent a value.
The conversion is explicit, but it can still discard information or produce
an invalid result when the source value is outside the destination type's
range.

For example:

```fsh
fn byte_index(offset: usize) -> u8 {
    return offset as u8; // warning[F0211]
}
```

`u8` can represent only `0..255`. An integer conversion to `u8` retains the
low eight bits, so an offset of `260` becomes `4`; it does not saturate at
`255`. A signed negative value converted to an unsigned type also becomes a
large unsigned value.

When converting a float to an integer, the fractional part is truncated
towards zero. The value must also be in the destination integer's range;
do not rely on an out-of-range conversion.

## What to do

- Validate the value against the destination range before converting.
- Clamp only when saturation is the intended behaviour.
- Keep the wider source type when the full value is meaningful.
- For floating-point conversions, round explicitly when rounding is wanted
  instead of truncation.

The language server reports the source and destination widths, destination
range, and the relevant conversion behaviour in the warning message.
